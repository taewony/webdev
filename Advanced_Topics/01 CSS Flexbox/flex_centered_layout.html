📚 레이아웃 부모-자식 관계 & 중앙 정렬 핵심 분석

🎯 전체 구조: <body>는 Flex 부모(세로 방향) → .container는 Flex 부모(가로 줄바꿈) → 각 .demo-card는 독립적인 카드. 각 카드 안의 .box는 서로 다른 중앙 정렬 기법을 적용받습니다.

🔹 1. Flexbox 방식 (.flex-center)
👉 부모-자식 관계: .flex-center 요소가 Flex Container(부모)가 되고, 그 안의 모든 직계 자식(텍스트 노드, 인라인 요소, 블록)은 Flex Item(자식)으로 간주됩니다.
👉 정렬 속성: justify-content: center → 주축(가로) 중앙, align-items: center → 교차축(세로) 중앙. 자식이 몇 줄이든, 어떤 콘텐츠든 항상 박스 정중앙에 위치합니다.
👉 장점: 반응형, 다중 줄, 블록 요소, 이미지 등 모든 콘텐츠에 완벽 대응. 실무에서 가장 널리 사용됨.

🔹 2. Line-height 방식 (.lh-center · 단일 줄)
👉 부모-자식 관계: 별도의 Flex 관계 없이, .box 자체가 블록 레벨 부모이며 line-height 속성이 인라인 자식(텍스트)의 라인 박스 높이를 결정합니다.
👉 작동 원리: height: 150px와 동일한 line-height: 150px를 부여하면, 한 줄 텍스트의 라인 박스 높이가 부모 높이와 같아져서 수직 중앙에 위치합니다.
👉 한계점: 여러 줄이 되면 각 줄마다 line-height(150px)가 적용되어 콘텐츠 전체 높이가 급증합니다. 위 3번째 카드에서 명확히 확인 가능 (텍스트가 박스 밖으로 잘리거나 레이아웃이 깨짐).

🔹 3. Line-height 실패 케이스 (다중 줄 데모)
👉 세 번째 카드는 동일한 line-height 값을 사용하면서도 세 줄의 텍스트를 넣어서 발생하는 문제를 직접 보여줍니다. overflow: hidden으로 인해 두 번째/세 번째 줄은 보이지 않거나 박스 영역을 벗어나 정렬이 완전히 무너집니다.
👉 이는 line-height 방식이 ‘단일 줄’에만 적합하다는 사실을 시각적으로 증명합니다.

💡 결론 & 실무 조언:
다양한 콘텐츠와 유지보수, 확장성을 고려할 때 Flexbox 방식이 모든 면에서 우수합니다. 부모-자식 관계를 명시적으로 제어할 수 있고, 여러 줄/복잡한 자식 요소에도 안정적인 중앙 정렬을 보장합니다.
Line-height 방식은 아이콘 폰트나 한 줄 버튼, 간단한 단일 텍스트에 한해 제한적으로 사용될 수 있지만, 일반적인 콘텐츠 박스에는 Flexbox(또는 Grid)를 권장합니다.
